# 训练算法总览

## 1. 当前系统

```text
raw query
  → Qwen3-0.6B Intent LoRA
  → BM25 + easy2 Embedding
  → 一级 Weighted RRF Top-20
  → bge-reranker-v2-m3
  → 二级 RRF Top-10
  → Qwen3-8B SFT → RPO → DPO Planner
```

模块之间的职责严格分开：Intent 只决定是否进入工具链；Embedding 和 BM25 负责召回；Reranker 提升候选顺序；Planner 只在固定 Top-10 内输出有序工具 ID。

## 2. Intent：LoRA SFT

Intent 模型使用自回归交叉熵学习严格 JSON 分类输出：

$$
\mathcal{L}_{\mathrm{SFT}}=-\sum_{t=1}^{T}\log p_\theta(y_t\mid x,y_{<t})
$$

LoRA 将权重增量写成低秩矩阵：

$$
W'=W+\frac{\alpha}{r}BA
$$

当前端点为 Qwen3-0.6B full LoRA `checkpoint-2000`，冻结 9K accuracy `1.0000`。检索输入仍是原始 query，不使用模型生成关键词。

## 3. Planner：跨风格 SFT

Planner 的输出空间是候选 Top-10 中的有序工具 ID 列表。SFT 使用 53,725 条 API-native 与 23,999 条 Legacy 训练样本，共 77,724 条。训练配置：

| 参数 | 数值 |
|---|---|
| Base | Qwen3-8B |
| GPU | 4×RTX 5090 |
| Epoch | 1 |
| LR | `5e-5` |
| Effective batch | 32 |
| LoRA | `r16/a32/dropout0.05` |
| Candidate order | canonical retrieval order |

SFT 负责学习候选读取、同类干扰拒绝、多工具依赖顺序和严格输出格式。端点为 `tooltrace-a3-crossstyle-sft8-4x5090-s20260728/checkpoint-2429`。

## 4. Embedding：显式负例 MNRL

给定一个 batch 中的 query $q_i$、正工具文本 $d_i^+$ 和其他负例，Multiple Negatives Ranking Loss 为：

$$
\mathcal{L}_{\mathrm{MNRL}}=-\frac{1}{B}\sum_{i=1}^{B}\log\frac{\exp(s(q_i,d_i^+)/\tau)}{\sum_j\exp(s(q_i,d_j)/\tau)}
$$

easy2 recipe 除 batch 内负例外，还加入跨领域和新增无关显式负例。其作用是提高召回边界，而不是学习 Planner 的工具执行顺序。

当前 Embedding：

- Base：`BAAI/bge-large-zh-v1.5`；
- Recipe：`easy2`；
- Seed：`20260731`；
- 输出：`PROJECT/data/rag/_aux/retrieval_pipeline_reselection/embedding_train/bge-large-reselection-easy2-s20260731/model/final`。

## 5. 一级检索：Weighted RRF

BM25 和向量检索各返回 Top-40。融合分数为：

$$
S(d)=\frac{1-w}{k+r_{\mathrm{BM25}}(d)}+\frac{w}{k+r_{\mathrm{vec}}(d)}
$$

当前参数 `w=0.8, k=5`。RRF 使用名次而不是未校准的原始分数，使词面召回和语义召回能够稳定组合。

## 6. Reranker：组内交叉熵

Reranker 对同一 query 的候选组输出分数 $z_j$，以 gold 工具为正类优化：

$$
\mathcal{L}_{\mathrm{rank}}=-\log\frac{\exp(z_+)}{\sum_j\exp(z_j)}
$$

当前模型是 `BAAI/bge-reranker-v2-m3`，使用 `mixed_typed3_mined4` 负例：类型相近干扰、来源挖掘 hard negative 与随机负例共同覆盖。学习率为 `2e-5`，候选深度为 20。

## 7. 二级融合

Reranker 不直接覆盖一级排序，而是在 exact Top-20 候选域内做第二次 RRF：

$$
S_2(d)=\frac{1-0.4}{8+r_{\mathrm{rerank}}(d)}+\frac{0.4}{8+r_{\mathrm{source}}(d)}
$$

最终取 Top-10 给 Planner。这样保留召回器的稳定先验，同时让 Cross-encoder 修正细粒度相似工具的顺序。每个 Planner 可见工具都经过 reranker 打分。

## 8. Planner 偏好优化

### 8.1 为什么在 SFT 后使用 DPO

SFT 已将 9K Full Trace 提升到 90.4556%，剩余错误不再主要是格式或任务理解，而是当前模型在固定候选中的具体偏好错误。直接收集当前父模型的错误输出，能构造与推理分布一致的 rejected。

偏好构造原则：

- 只从训练侧全新 query 挖掘；
- rejected 必须是当前父模型真实 greedy 输出；
- 只保留严格可解析但集合或顺序错误的样本；
- gold 工具必须全部位于 Top-10；
- 每个 query/source 最多一对；
- 工具数 1～6、错误类型和 100 工具覆盖均衡；
- 与开发集及冻结集零重叠。

### 8.2 DPO

对 chosen $y_w$ 和 rejected $y_l$：

$$
\mathcal{L}_{\mathrm{DPO}}=-\log \sigma\left(\beta\left[\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}\right]\right)
$$

本轮固定 `beta=0.1`。reference adapter 固定，防止不同训练阶段改变 KL 锚点。

### 8.3 RPO chosen-NLL 锚点

纯 DPO 只要求 chosen 相对 rejected 更优，不保证 chosen 自身的绝对似然持续上升。RPO 加入 chosen NLL：

$$
\mathcal{L}=\mathcal{L}_{\mathrm{DPO}}+\alpha\mathcal{L}_{\mathrm{NLL}}(y_w\mid x)
$$

主阶段四卡并行比较 DPO 与 `alpha=0.5/1.0` 的 RPO，最优为 `alpha=0.5, lr=1e-6`。这一步把开发 TraceEM 推到 `0.8825`。

### 8.4 自适应短程 DPO

因为主阶段最优点位于 1 epoch 边界，从最优 checkpoint 再延长 0.5 epoch，比较四个低学习率配方。28 个 checkpoint 在同一 1,200 条独立开发集上评测，最终锁定纯 DPO `lr=5e-7, checkpoint-113`，开发 TraceEM `0.888333`。

这种两段式训练不是固定堆叠轮数：只有在可观察的开发曲线边界仍上升时才扩展，并用更小步长控制过优化。

## 10. 选参与评测纪律

1. 所有数据先做生成与隔离审计；
2. 检索接口在 Planner 训练前固定；
3. Planner 只用 1,200 条独立开发集选择 checkpoint；
4. 主指标是 original-order RAG TraceEM，SetEM、Strict 和 conditional TraceEM 为守门指标；
5. Legacy 6K、API 1K 和系统 9K 只在端点锁定后报告；
6. API 1K 出现一个净回退也不回看调整端点。
