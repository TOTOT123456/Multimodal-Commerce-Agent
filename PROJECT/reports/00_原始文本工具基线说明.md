# 100 工具电商导购 Agent

这是一个面向 100 个电商工具的分层 LLM Agent 实验：先判断用户是否需要工具，再召回和重排工具候选，最后由 Planner 输出完整且有序的工具 ID Trace。

## 最终结果

当前 9,000 条静态系统评测达到：

| 指标 | 正确数 | 准确率 |
|---|---:|---:|
| Full Set | 8,352 / 9,000 | 92.8000% |
| Full Trace | 8,336 / 9,000 | **92.6222%** |

其中 9K 由 6,000 条电商 query 和 3,000 条闲聊组成。Intent 路由准确率为 100%；电商样本继续进入检索与 Planner。

`Full Trace` 检查路由和有序工具 ID 是否正确，不包含真实工具参数、API 执行或交易完成。

## 当前系统

```text
原始 query
  → Qwen3-0.6B Intent LoRA
  → BM25 + easy2 Embedding，各 Top-40
  → 一级 Weighted RRF（vector_weight=0.8, k=5）
  → bge-reranker-v2-m3 exact Top-20
  → 二级 RRF（source_weight=0.4, k=8）
  → Top-10
  → Qwen3-8B SFT → RPO → DPO Planner
  → 有序工具 ID Trace
```

唯一机器可读路由入口是 [`PROJECT/configs/retrieval_canonical_route.json`](PROJECT/configs/retrieval_canonical_route.json)。Planner 偏好训练入口是 [`PROJECT/configs/assignment3_current_dpo.json`](PROJECT/configs/assignment3_current_dpo.json)。多轮运行时锁定配置是 [`PROJECT/configs/agent_runtime.json`](PROJECT/configs/agent_runtime.json)。

## Planner 训练

Qwen3-8B 先使用 77,724 条跨风格数据完成 4×RTX 5090 LoRA SFT：53,725 条 API-native 与 23,999 条 Legacy train。SFT 的 Legacy TraceEM 为 `0.856833`，9K Full Trace 为 `0.904556`。

偏好优化只使用训练侧新生成 query 和当前父模型真实错误。长链与短链面板分别观察到 6,734/1,683 个严格语义错误，跨面板去重后为 8,309 个，再按工具数、错误类型和工具覆盖分层选择 4,000 对：

| Gold 工具数 | 1 | 2 | 3 | 4 | 5 | 6 |
|---:|---:|---:|---:|---:|---:|---:|
| 偏好对 | 200 | 600 | 800 | 800 | 800 | 800 |

4 张 5090 并行比较纯 DPO 和带 chosen-NLL 锚点的 RPO。主阶段由 RPO 推进；开发曲线最优点位于边界后，再自适应延长 0.5 epoch，以低学习率纯 DPO 收敛。总计比较 28 个 checkpoint，最终端点为：

```text
PROJECT/finetune/outputs/
  tooltrace-a3-planner-dpo2-ext-dpo-lr5e7-s20260819/checkpoint-113
```

独立开发集 TraceEM 从 `0.856667` 提升到 `0.888333`，改善/回退 `42/4`；锁定后 Legacy 6K TraceEM 提升到 `0.889333`，相对起始父模型改善 `3.1333pp`。

## 多轮 Agent 架构

当前已加入模型外多轮层：自包含 query 原样进入既有链路；指代、取消、修正和显式继承先解析为短 `resolved_query`，再调用同一个 Intent、Top-10 检索和最终 DPO Planner。SQLite 保存会话隔离的事件、紧凑状态与长期记忆，并提供 Token 硬门、版本冲突检测、TTL 和删除接口。

隔离 dev 上比较 A/B/C/D/E、近期窗口 2/3/4、长期记忆 Top-K 1/2/3 和输入目标 640/768/1,024，共 73 个配置，锁定 `E-n2-k2-t640`。封存 test 只打开一次：

| 多轮评测 | Overall TraceEM | 上下文依赖 | 上下文无关 | Strict | 输入 Token p95 |
|---|---:|---:|---:|---:|---:|
| Dev 594 | 0.774411 | 0.710938 | 0.791845 | 1.000000 | 449 |
| Test 594 | **0.771044** | **0.671875** | 0.798283 | 1.000000 | 449 |

```bash
python3 -m unittest discover -s PROJECT/tests -v
```

31 项无模型架构测试和 5 项故障注入已通过；已有预测上的真实后端复现检查为 Intent `20/20`、RAG `20/20`、Planner `1/1` 逐字段一致。Legacy 6K/API 1K 的首轮 query 恒等率均为 1.0，因此静态 TraceEM 保持 0.889333/0.994000。多轮结果仍只代表 100 工具合成闭集，尤其 test 上下文依赖 TraceEM 0.671875 说明仍有改进空间。

## 数据与实验边界

- Catalog：100 个工具，校验 `errors=0`。
- Legacy：train 24,000 / frozen test 6,000。
- Intent frozen：9,000，其中电商 6,000、闲聊 3,000。
- API frozen：1,000，仅作 Planner 补充分布评测。
- Planner development：1,200，仅作 checkpoint 选择。
- Multi-turn dev/test：594/594；各 148 个会话、128 条上下文依赖轮次，test 只打开一次。
- train/test 的 normalized query、trace id、表达簇和上下文骨架隔离审计通过。
- 冻结 query、gold、预测和由其派生的信息不进入 SFT、负例挖掘或偏好训练。
