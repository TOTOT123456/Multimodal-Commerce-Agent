完整流程包含数据构建、SFT 数据准备、隔离审计、基座评测与 LoRA checkpoint 评测。核心结果如下：

- 正式 Intent 端点为 `Qwen3-0.6B full_lora checkpoint-2000`。当前系统只消费路由类别，检索继续读取原始 query，不消费预测关键词；1.7B final 仅保留为关键词抽取能力更强的历史对照。

## 4. 关键词抽取质量

### 4.1 评测口径

关键词 gold 由工具 ID 一一映射到 Catalog 的 100 个 `keyword_label`。本节只评测 6,000 条 gold 电商样本，避免 3,000 条闲聊空标签抬高分数；这 6,000 条共有 15,196 个 gold 关键词实例。

- 用中英文逗号、顿号、分号、竖线、斜线和换行切分，去除首尾空白与句末标点，再按集合去重。
- `Exact` 要求一条 query 的关键词集合完全一致。
- `micro-P/R/F1` 汇总所有 query 的 TP/FP/FN；`sample-F1` 是逐 query F1 的平均。
- `Catalog-valid` 是预测关键词中恰好属于 100 个 Catalog label 的比例。
- 这是**字面规范标签**评测，不是 LLM-judge 语义覆盖分；同义改写但不等于规范 label 时仍记为不匹配。

### 4.2 全模型结果

| 模型 | 阶段 | Exact | micro-P | micro-R | micro-F1 | sample-F1 | Catalog-valid |
|---|---|---:|---:|---:|---:|---:|---:|
| Keyword baseline | lexical | 0.0000 | 0.0000 | 0.0000 | 0.0000 | 0.0000 | - |
| Qwen3-0.6B | 基座 | 0.0000 | 0.0029 | 0.0036 | 0.0032 | 0.0020 | 0.0230 |
| Qwen3-0.6B | full_lora best | 0.5613 | 0.8101 | 0.8319 | 0.8208 | 0.8241 | **0.9619** |
| Qwen3-0.6B | full_lora final | **0.5783** | **0.8201** | 0.8453 | 0.8325 | 0.8361 | 0.9553 |
| Qwen3-1.7B | 基座 | 0.0000 | 0.0021 | 0.0020 | 0.0020 | 0.0008 | 0.0085 |
| Qwen3-1.7B | balanced_lora best | 0.5465 | 0.7898 | 0.8645 | 0.8254 | 0.8240 | 0.9395 |
| Qwen3-1.7B | balanced_lora final | 0.5782 | 0.8115 | **0.8723** | **0.8408** | **0.8383** | 0.9443 |

结论不能只写“分类 100%”：0.6B best 虽然分类完全正确，关键词 Exact 仍只有 56.13%。1.7B final 的关键词 micro-F1 更高，但当前 canonical RAG 使用原始 query，不消费预测关键词，这项优势不会传导到检索或 Planner。正式路由因此使用 0.6B best；`checkpoint-2000` 仍是训练阶段产生的 Swift best checkpoint，不是在冻结 9K 上重新挑出的 checkpoint。端点比较已经观察过固定 9K，真实流量外推仍需新的线上风格数据。

## 5. 推理效率

固定 9000 条集合上的效率口径如下：

- 关键词规则使用 Montage Jintide C6230R 单线程。
- 六个神经模型版本分别在单张 NVIDIA GeForce RTX 3090 24GB 上运行；PyTorch 2.8.0+cu128、Transformers 4.53.2、PEFT 0.14.0。
- 神经模型统一使用 BF16、贪心生成、`max_new_tokens=48` 和 3 个不计时预热批次；0.6B / 1.7B 批量分别为 64 / 48。
- p50 / p95 是 `model.generate` 批次墙钟时间除以批量后的离线均摊，不是在线单请求延迟；样本吞吐也不含 prompt 构建与分词。

| 评测对象 | 版本 / 执行方式 | 批量 | 均摊处理均值 | p50 / p95 | 样本吞吐 | 输出吞吐 | 峰值显存 allocated / reserved |
|---|---|---:|---:|---:|---:|---:|---:|
| Keyword baseline | 单线程 CPU | 1 | 0.1144ms | 0.1066 / 0.1493ms | 8727.45 条/s | - | - |
| Qwen3-0.6B | 基座 | 64 | 36.92ms | 37.23 / 38.35ms | 27.08 条/s | 683.07 token/s | 3.65 / 4.73 GiB |
| Qwen3-0.6B | full_lora best，step 2000 | 64 | 45.66ms | 45.47 / 49.05ms | 21.90 条/s | 342.21 token/s | 4.04 / 5.10 GiB |
| Qwen3-0.6B | full_lora final，step 2852 | 64 | 45.33ms | 44.83 / 54.11ms | 22.06 条/s | 345.20 token/s | 4.04 / 5.10 GiB |
| Qwen3-1.7B | 基座 | 48 | 54.01ms | 54.64 / 58.57ms | 18.52 条/s | 447.31 token/s | 5.43 / 5.86 GiB |
| Qwen3-1.7B | balanced_lora best，step 1600 | 48 | 69.62ms | 69.58 / 75.51ms | 14.36 条/s | 228.02 token/s | 6.09 / 6.85 GiB |
| Qwen3-1.7B | balanced_lora final，step 2852 | 48 | 69.41ms | 69.24 / 75.82ms | 14.41 条/s | 227.15 token/s | 6.09 / 6.85 GiB |

逐版本计时证据位于 `PROJECT/finetune/outputs/preds/intent_efficiency_20260731/`。这些文件用于效率与资源比较；模型质量仍以上一节列出的冻结预测文件和指标为准。

相对原 1.7B final，正式 0.6B best 的生成 p50 从 `69.24ms` 降至 `45.47ms`（约 `-34.3%`），吞吐从 `14.41` 提升至 `21.90` 条/s（约 `+52.0%`），峰值 allocated 显存从 `6.09` 降至 `4.04 GiB`（按原始值约 `-33.6%`）。这些均是 Intent 模块的离线 batch 指标，不等于整条检索与 Planner 链路的端到端降幅。
