为了防止偏好数据被 3～6 工具长链垄断，另生成 12,000 条 1～2 工具 query；11,867 条检索可达，父模型 TraceEM 为 `0.858178`，得到 1,683 个真实错误，其中单工具 203 个、双工具 1,480 个。

- 输出必须严格解析，且与 gold 的集合或顺序确实不等价；
- query、ID、表达簇和上下文骨架隔离审计 `strict_ok=true`。

## 7. 算法与训练

### 7.1 DPO 与 RPO

对偏好三元组 $(x,y_w,y_l)$，DPO 优化：

$$
\mathcal{L}_{\mathrm{DPO}}=-\log \sigma\left(\beta\left[\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}\right]\right)
$$

主阶段额外加入 chosen 的负对数似然锚点：

$$
\mathcal{L}=\mathcal{L}_{\mathrm{DPO}}+\alpha\mathcal{L}_{\mathrm{NLL}}(y_w\mid x)
$$

它使模型在推开 rejected 的同时直接保持正确工具链概率，尤其适合格式短、类别离散的 Planner 输出。reference adapter 始终固定为起始 DPO `checkpoint-29`，不会随训练阶段漂移。

### 7.2 四卡主搜索

4 张 RTX 5090 同时训练四个配方；公共配置为 `beta=0.1`、1 epoch、有效 batch 16、LoRA `r16/a32/d0.05`、seed `20260817`：

| Loss | LR | RPO alpha |
|---|---:|---:|
| DPO | `5e-7` | 0 |
| DPO + RPO | `5e-7` | 0.5 |
| DPO + RPO | `5e-7` | 1.0 |
| DPO + RPO | `1e-6` | 0.5 |

主阶段最优是 `RPO alpha=0.5, lr=1e-6, checkpoint-225`，开发 TraceEM `0.8825`。最优点位于训练边界，说明仍有可控增益，因此触发短程扩展。

### 7.3 自适应短程扩展

从 `checkpoint-225` 再训练 0.5 epoch，比较纯 DPO `5e-7` 与 RPO alpha 0.5 的 `1e-6/5e-7/2e-7`。28 个主阶段与扩展阶段 checkpoint 全部在同一 1,200 条开发集评测。

最终选择纯 DPO `lr=5e-7, checkpoint-113`。它的开发聚合指标与一个持续 RPO 端点并列，选择器按最后一项 `name asc` 确定性破平；冻结集没有参与破平。

## 11. 结论边界

- Full Trace 只检查静态路由和有序工具 ID，不检查参数生成、真实 API 成功、状态变更或多轮恢复。
- 结果来自 100 工具合成闭集，不能直接外推到线上表达漂移或新增工具。
- 本轮最明显的收益来自“当前父模型真实错误 + 长短链均衡 + RPO 主推进 + DPO 短收敛”，而不是无边界增加偏好对数或训练轮数。
